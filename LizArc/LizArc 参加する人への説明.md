# LizArc 参加する人への説明

2026-11-19 に書きました。くわしい記録は、同じフォルダの「LizArc 学習方法の設計」にあります。この説明だけ読めば、手伝いを始められるようにしてあります。

## 1. LizArc とは

文章や画像から、マインクラフトの建築を自動で作る AI です。できた建築は、Litematica の設計図（`.litematic`）として出します。

今は、**学習のしかたを 1 つに決める段階**です。動く製品は、まだありません。

## 2. 今の作り方

| 段 | すること | 担当 |
|---|---|---|
| ① 形づくり | 文章から、建物の粗い形を書く（ふつうのブロックだけ） | Claude Code が「形の書き方」で書き、Rust のプログラムがブロックに直す |
| ② 仕上げ | 粗い形に、階段・ハーフ・柵・板ガラスなどの細部を足す | 学習したモデル（ここが LizArc の本体） |
| ③ 書き出し | `.litematic` にする | Rust のプログラム |

② のモデルは、「本物の建築から細部を消したもの」を見せて、「元に戻す」練習をさせて学習します。

## 3. 今どこまで来たか

- **流れは通りました。** 文章から設計図まで、人の手を入れずに動きます（2026-11-19）。
- **出来は、まだ判断できていません。** ゲームで見て確かめるのは、これからです。
- **いちばんの課題は、建築の「種類」です。** 同じ作者のマップで学習すると、そのマップの中では細部を 7 割近く戻せます。ところが、別のマップでは 2 割しか戻せません。区画の量を 4 倍にしても変わらず、マップの種類を増やすと上がりました。
- **今は、181 人が建てた家のデータ（3D-Craft）で、「家を増やすほど上がるか」を測っています。**

## 4. お願いしたいこと

できるものから、1 つずつで大丈夫です。A がいちばん助かります。

### A. ゲームで確かめる（マイクラ 26.3 と Litematica が要る）

**A-1. 検査盤を開く。** `lizarc_testboard.litematic` を Litematica で開いて、次の 5 点を見てください。

1. 青い列（ラピスラズリ）が北の端、赤い列（レッドストーン）が東の端にある。
2. 階段 8 個（下付き 4、逆さ 4）の高い側が、どれも金ブロックのほうを向いている。
3. ハーフが、下・上・二重の順に並んでいる。
4. 開いたトラップドア 4 個が、どれも金ブロックに張り付いている。
5. 原木の年輪の面が、東西・上下・南北の順に並んでいる。

報告：5 点それぞれについて、「合っている」か「違う（どう違うか）」を教えてください。画像があると助かります。

**A-2. 試作の家を見る。** 設計図の中に、同じ家が 2 つ、東西に並んでいます。西が「粗い形」、東が「モデルが細部を足したもの」です。

報告してほしいこと：

- 開けたか。壊れたブロックや、紫（赤紫の羊毛）のブロックがないか。紫は「モデルが決められなかった所」の印です。
- 階段の向きは自然か。屋根の角は、きれいにつながっているか。
- 板ガラスや柵は、となりとつながっているか。
- 西と東を比べて、東のほうが良くなっているか。10 点満点で、それぞれ何点か。
- 「ここが変」と思った所。画像があると助かります。

試作の設計図は、学習が終わるたびに新しくなります。どの設計図を見たか（ファイルの名前と日付）も書いてください。

### B. 建築と文章（マイクラが要る。プログラムは不要）

**B-1. 作ってほしい建物を、文章で書く。** 20〜30 個あると助かります。短くてかまいません。

- 例：「丸石の土台、白樺の板の壁、レンガの切妻屋根と煙突のある小さな家」
- 大きさ、素材、屋根の形、塔や煙突などの特徴を入れてください。
- 家だけでなく、塔、橋、門、倉庫、井戸なども混ぜてください。
- 最初は、32×32×32 ブロックに収まる大きさが助かります。

**B-2. お手本の建築を提供する。** 自分で建てた建築を、Litematica で `.litematic` に保存して渡してください。

- **自分で建てたものだけにしてください。** ほかの人の作品や、配布サイトから落としたものは、使えません。
- 階段、ハーフ、柵、板ガラスなどの細部が多い建築ほど、学習に役立ちます。
- 渡すときに、次の 2 つを書いてください。「AI の学習に使ってよいか」「将来、収益化するモデルの学習にも使ってよいか」。

### C. 学習を手伝う（NVIDIA の GPU が要る）

自分のパソコンで学習を回して、結果のファイルを送り返す手伝いです。準備は 6 章にあります。

**GPU は、準備のスクリプトが自動で調べます。** GPU の名前とメモリの量、今の設定で学習できるかの判定が出ます。その表示を、そのまま送ってください。今の設定は、GPU のメモリを約 10GB 使います。「メモリが足りません」と出たときは、設定を変える必要があるので、学習を始めずに知らせてください。

あとから調べ直すときは、次のコマンドです。

```powershell
.venv\Scripts\python.exe -I -X utf8 tools\gpu_check.py
```

**学習は、GPU を使いすぎないようになっています。** 準備のスクリプトが、「GPU 全体の使用率が 50% くらいになるように、自動で加減する」設定にします。学習が GPU 全体の使用率を 2 秒ごとに測り、ほかのプログラムが GPU を使っていれば、そのぶん自分の取り分を減らします。GPU の種類は問いません。

お願いしたい学習は、次の 3 つです。上から順に役立ちます。

| 名前 | 中身 | 何が分かるか |
|---|---|---|
| `c3d_all_s1`、`c3d_all_s2` | 全部の家で、乱数の種だけを変えて 2 回 | 同じ条件でやり直したときに、成績がどのくらい揺れるか。今は 1 回ずつしか回せておらず、いちばん弱い所です |
| `c3d_all_long` | 全部の家で、歩数を 20,000 に延ばす | 長く学習すると、まだ伸びるか |
| `c3d_800` | 家 800 軒 | 家の数と成績の関係の、あいだの点 |

始めるコマンド（PowerShell で、プロジェクトのフォルダの中で）：

```powershell
.venv\Scripts\python.exe -I -X utf8 train\lizarc_train.py --run c3d_all_s1 --data ds_c3d --seed 1 --max-steps 6000 --eval-every 1000
```

```powershell
.venv\Scripts\python.exe -I -X utf8 train\lizarc_train.py --run c3d_all_s2 --data ds_c3d --seed 2 --max-steps 6000 --eval-every 1000
```

```powershell
.venv\Scripts\python.exe -I -X utf8 train\lizarc_train.py --run c3d_all_long --data ds_c3d --max-steps 20000 --eval-every 2000
```

```powershell
.venv\Scripts\python.exe -I -X utf8 train\lizarc_train.py --run c3d_800 --data ds_c3d --train-fraction 0.4115 --max-steps 6000 --eval-every 1000
```

終わったら、外し方の調べも回してください（`c3d_all_s1` の所は、学習の名前に替えます）。

```powershell
.venv\Scripts\python.exe -I -X utf8 train\diagnose.py --run c3d_all_s1 --chunks 2048 --out runs\c3d_all_s1\diagnose.txt
```

- **かかる時間。** RTX 4080 SUPER で、6,000 歩が 35〜80 分です（ほかの作業と GPU を分け合うと遅くなります）。
- **途中で止めたいとき。** `runs\学習の名前\PAUSE` という名前の空のファイルを作ると、その時点を保存して終わります。同じコマンドをもう一度実行すると、続きから始まります。
- **GPU の使い方を変えたいとき。** `runs\GPU_LIMIT` というファイルを、メモ帳で書き換えます。学習中に書き換えても、10 秒ほどで効きます。
    - `total 50` … GPU 全体の使用率が 50% くらいになるように、自動で加減する（最初の設定）。数字は 10〜100 で変えられます。
    - `55` … 学習の取り分を 55% に固定する（ほかのプログラムの分は見ない）。
    - ファイルを消す … 休まずに全力で学習する。
- **使用率を抑えると、学習は遅くなります。** 歩数で止める学習なので、結果は変わりません。**GPU のメモリ（約 10GB）は減りません。** ゲームなどでメモリが要るときは、学習を止めてください。
- **重いゲームを動かしている間は、学習はほとんど進みません。** ゲームだけで GPU 全体が 50% を超えると、学習の取り分は下限（5%）まで下がります。
- **送り返すもの。** `runs\学習の名前\log.jsonl` と `diagnose.txt` の 2 つです。どちらも小さい文字のファイルです。重み（`ckpt.pt`、約 490MB）は、頼まれたときだけで大丈夫です。
- **コマンドの数字や設定は、変えないでください。** 変えると、こちらの成績と比べられなくなります。変えたほうが良さそうな所に気づいたら、先に教えてください。

## 6. 準備（C と D をする人だけ）

Windows のパソコンでの手順です。A と B だけなら、この章は要りません。

**入れておくもの。**

| もの | 何に使うか |
|---|---|
| Git for Windows | プログラムの受け取りと、家のデータの展開 |
| Python 3.12 | 学習と変換 |
| Rust（rustup） | ブロックの回転の表づくり、設計図の書き出し |
| PowerShell 7（`pwsh`） | 準備のスクリプト |
| NVIDIA のドライバー | GPU での学習 |

**手順。** プロジェクトのフォルダの中で、上から順に実行します。

1. Python の環境を作ります。

```powershell
py -3.12 -m venv .venv
```

2. 学習の道具を入れます。元のパソコンは、PyTorch 2.15.0（CUDA 13.2 用）と NumPy 2.5.5 です。

```powershell
.venv\Scripts\python.exe -m pip install numpy==2.5.5 torch==2.15.0 --index-url https://download.pytorch.org/whl/cu132 --extra-index-url https://pypi.org/simple
```

3. GPU が使えるかを確かめます。`True` と出れば大丈夫です。

```powershell
.venv\Scripts\python.exe -I -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

4. Rust のプログラムが動くかを確かめます。22 個のテストが通れば大丈夫です。

```powershell
cargo test --release
```

5. 家のデータを落として、学習の形に変換します（537MB のダウンロード。全部で 5〜10 分）。

```powershell
pwsh tools\c3d_setup.ps1
```

最後に「準備ができました。データは、元のパソコンのものと同じです。」と出れば、学習を始められます。「違います」と出たときは、学習を始めずに知らせてください。

**この手順で、確かめられていないこと。**

- 手順 1〜2（Python の環境づくり）は、元のパソコンとは別のやり方で書いています。同じ版が入ることは、確かめていません。うまく入らないときは、出た文字をそのまま送ってください。
- 手順 5 のうち、「ダウンロード」と「展開」の部分は、元のパソコンでは通して試していません（すでに落としてあったためです）。変換から後ろは、試して、同じデータになることを確かめました。

## 7. フォルダの中身

| 場所 | 中身 |
|---|---|
| `src\` | Rust のプログラム。設計図の読み書き、形の書き方、柵や階段のつながりの計算 |
| `train\` | 学習（`lizarc_train.py`）、外し方の調べ（`diagnose.py`）、細部を足す（`detail.py`） |
| `tools\` | データの変換、準備、学習の開始と一時停止 |
| `shapes\` | 形の書き方で書いた建物 |
| `data\` | 学習データ。**共有には入っていません**（各自が落として作る） |
| `runs\` | 学習の記録と重み。**共有には入っていません** |
| `out\` | できた設計図など。**共有には入っていません** |

## 9. 言葉の説明

| 言葉 | 意味 |
|---|---|
| 細部 | 階段、ハーフ、塀、柵、板ガラス、ドア、トラップドアなど、ブロックの一部だけを占めるもの |
| 粗い形 | 細部がなく、ふつうのブロックだけでできた建物 |
| 区画 | 32×32×32 ブロックの箱。モデルは、この大きさずつ見る |
| 歩 | 学習で、重みを 1 回直すこと |
| 検証 | 学習に使っていない建築で、成績を測ること |
| 基準 | 「崩したまま何もしない」ときの成績。モデルは、これを上回らないと意味がない |
| 重み | モデルが学習で身につけた数字のかたまり。`ckpt.pt` に保存される |
