### 学習の止め方と、様子の見方

`D:\Claudcode\Liz_ARC` にある 3 つのファイルを、ダブルクリックします。

| ファイル | すること |
|---|---|
| `学習を一時停止.bat` | その時点を保存して、学習を終了する。GPU が完全に空く |
| `学習を再開.bat` | 保存した所から続ける |
| `学習の様子.bat` | 進み具合と、検証の成績を表示する |

一時停止をしなくても、10 分ごとに自動で保存しています。

**ふだんは、どれも起動しなくてかまいません。** 学習は Claude Code が始めて、決めた時間で自動的に終わります。3 つのファイルは、あなたが使いたいときだけの道具です。

| こんなとき | 使うファイル | 回数 |
|---|---|---|
| ゲームなどで GPU を使いたい。パソコンを切りたい | `学習を一時停止.bat` | 1 回。「止まりました」と出れば終わり |
| 用事が済んで、続きをさせたい | `学習を再開.bat` | 1 回。「始めました」と出れば終わり。画面は閉じてよい |
| 今どうなっているか見たい | `学習の様子.bat` | 好きなときに何回でも。見るだけで、学習には影響しない |

- **まちがえて押しても、壊れません。** 動いていないときに一時停止を押す、終わった学習を再開する、2 回押す、のどれも「何もしなくて大丈夫です」と表示するだけです（2026-11-18 に直して、試しました）。
- **一時停止をしても、学習時間の上限は引き継ぎます。** 3 時間の学習を 1 時間で止めて再開すると、残りの 2 時間だけ進んで終わります。
- **一時停止を忘れてパソコンを切った場合**は、最後の自動保存（10 分以内）まで戻ります。`学習を再開.bat` で続けられます。
- **学習が終わっても、Claude Code には通知が来ません。** 終わったころに Claude Code に声をかけると、結果を読んで、この設計書を更新します。
- **いくつかの学習を順番に回しているとき（2026-11-19 から）も、使い方は同じです。** `学習を一時停止.bat` は、今の学習を止め、次の学習も始まらないようにします。`学習を再開.bat` で、止めた所から続き、残りも順番に回ります。`学習の様子.bat` には、全体の進み（何個のうち何個が終了か）も出ます。短い試し運転で確かめました。
- **パソコンを再起動した場合だけ、順番待ちが切れます。** `学習を再開.bat` で今の学習は続けられますが、次の学習は自動では始まりません。Claude Code に声をかけてください。

### 最初の学習 v0

**崩し方。** 本物の区画（32×32×32）を、次のように粗くします。

1. 階段・ハーフ・塀を、同じ素材のふつうのブロックに置き換える。
2. トラップドア、柵、板ガラス、飾り、植物を消す。
3. 2×2×2 ごとに多数決を取って、1 ブロックの凹凸をつぶす。

これは、「3D モデルを色合わせだけでブロックに変換した結果」をまねたものです。

**当てさせ方。** 崩した区画を見せ、元の区画の一部を隠して、隠した所を当てさせます。ぜんぶ隠せば「一度に全部当てる方式」、少しずつ開ければ「数回に分けて埋める方式」になります。1 つのモデルで、両方を試せます。

**モデル。** 重みは約 4,070 万個です。1 秒に約 3.4 歩（1 歩で 16 区画）進みます。3 時間で、学習データを約 5 周します。GPU のメモリは、約 12GB を使います。

**検証。** 学習に一度も使わないマップ（marethea）の 256 区画で測ります。測るのは次の 3 つです。

| 測るもの | 意味 |
|---|---|
| 当たり | ブロックのある所で、本物と同じブロックを置けた割合 |
| 細部を当てた割合 | 本物の階段・ハーフ・塀などのうち、種類も向きも当てた割合 |
| 細部の量 | 本物の細部の数に対して、モデルが置いた細部の数 |

**比べる相手。** 「崩したまま何もしない」が基準です。これは、あなたの Blender 案を、仕上げなしで使った場合に当たります。当たりは 48.6%、細部は 0% です。

#### v0 の結果と原因（2026-11-18、3 時間、26,826 歩）

**結論。関門 2 は通っていません。** 当たりは基準を 3 ポイント上回りましたが、いちばん大事な細部は、ほぼ当たりませんでした。

| | 当たり | 細部を当てた割合 | 細部の量 |
|---|---|---|---|
| 崩したまま（基準） | 48.6% | 0% | 0% |
| 一度に全部当てる方式 | 51.8% | 1.1% | 8% |
| 数回に分けて埋める方式 | 56.4%（※） | 1.2% | 71% |

- **成績は、始めて 30 分（6,000 歩）で頭打ちになりました。** そのあと 2 時間半、検証の成績は変わっていません。学習を長くしても良くならない、ということです。
- **数回に分けて埋める方式は、細部を本物の 7 割ほど置きますが、場所が合っていません。** 置いた細部のうち、合っていたのは 1.7% です。
- ※ 数回に分ける方式は 24 区画だけで測っています。256 区画で測ったほかの 2 つとは、直接は比べられません。
- 「細部を当てた割合」は、1 ブロックずれただけでも外れになる、厳しい測り方です。

**原因を調べました（`train\diagnose.py`）。** 学習に使った区画と、使っていない区画で、それぞれ 256 区画を測りました。

| | 粗くした立体から戻す（本番と同じ） | 粗くせず、素材だけ直した立体から戻す |
|---|---|---|
| 学習に使った区画：当たり | 70.5% | 94.2% |
| 学習に使った区画：細部を当てた割合 | 22.6% | 57.3% |
| 使っていない区画：当たり | 52.8% | 82.3% |
| 使っていない区画：細部を当てた割合 | 1.1% | 15.3% |

ここから、原因が 2 つ分かりました。

1. **モデルは、学習した建築を覚えただけです。** 学習に使った区画では細部が 22.6% 当たるのに、使っていないマップでは 1.1% です。「どんな所に階段を置くか」という決まりを学んだのではなく、見た建築を暗記しています。学習データは 5 つのマップだけで、しかも区画が重なっているので、中身が少なすぎます。
2. **崩し方が強すぎます。** 2×2×2 の多数決で、1 ブロックの厚みしかない屋根のふちや手すりが、丸ごと消えます。使っていない区画では、本物の細部がある所の 79% に、モデルは空気を置きました。手がかりが残っていないので、当てようがありません。

もう 1 つ、悪い知らせがあります。**粗くしない場合でも、使っていない区画では、何もしないほうがましでした。** 何もしないと当たりは 83.6% で、モデルは 82.3% です。細部を少し当てる代わりに、ふつうのブロックを余計に細部へ変えて、差し引きで損をしています。

**良い知らせもあります。** 粗くしない場合、使っていない区画でも、本物の細部の 63% は「モデルの上位 5 つの候補」に入っていました。まったく学べていないわけではありません。

**次の学習（v1）で変えること。** 上の 2 つの原因に、順に手を打ちます。

| 変えること | ねらい |
|---|---|
| 崩し方を弱める。多数決をやめ、1 ブロック単位の形は残す | 手がかりを残す。3D モデルをブロックに変換した結果にも、こちらのほうが近いはず（未確認） |
| 「素材」と「形（階段・ハーフ・向き）」を分けて当てさせる | 素材が違う建築でも、形の決まりは使い回せるようにする |
| 検証を 2 種類にする：同じマップの別の場所と、別のマップ | 「暗記」なのか「マップごとの作風の違い」なのかを見分ける |
| 左右反転を足し、区画の重なりを減らす | 暗記をしにくくする |

これで細部が当たらなければ、「このデータ量では足りない」が答えになります。その場合は、データを増やす（色の残っている建築を探す）のが先になります。

### 2 回目の学習 v1（2026-11-18 19:40〜22:14、2 時間、21,847 歩）

v0 で見つけた 2 つの原因に、手を打った版です。プログラムは `train\lizarc_train.py`（v0 は `train\lizarc_train_v0.py` に残してあります）。

**結論。関門 2 は「半分通過」です。**

- **同じマップの、学習に使っていない場所では、はっきり効きました。** 当たりは 95.1%（基準 86.5%）。消された細部の 3 分の 2 を、形も素材も合わせて戻せています。
- **暗記は、なくなりました。** 学習に使った区画と、使っていない場所で、成績がほぼ同じです。v0 のいちばんの問題は直りました。
- **別のマップでは、ほとんど効いていません。** 当たりは 84.7%（基準 83.6%）で、上回ったのは 1 ポイントだけです。細部は 2 割しか当たりません。
- **足りないのは、学習の時間ではなく、マップ（作風）の種類だと見ています。** 別のマップの成績は 45 分あたりから横ばいでした。学習用のマップは 5 つだけです。これは私の見立てで、次の実験で確かめます（下の「次にやること」）。

細かい数字は、下の「最後の成績」にあります。

**v0 から変えたこと。**

| 変えたこと | 中身 |
|---|---|
| 崩し方を弱めた | 2×2×2 の多数決をやめた。1 ブロック単位の形は残す。細部は素材のブロックに直し、一部だけ消す（階段 10%、ハーフ 50%、塀 70%）。飾りは消す |
| 「素材」と「形」を分けて当てる | 例：クォーツの階段 → 素材「クォーツ」＋形「階段・東向き・上付き」。素材 197 種、形 303 種。分けて戻しても、元と違ってしまうブロックは 0.13% だけ |
| 検証を 2 種類にした | ① 学習用のマップから取り置いた区域（128×128 ブロックの区域を 1 割。10,644 区画）② 別のマップ（marethea。v0 と同じ 256 区画） |
| 左右反転を足した | 回転 4 通り × 反転 2 通りで、見本が 8 倍になる。反転の決まりは Rust に書き、階段の角の形が正しく移ることをテストで確かめた |

学習に使う区画は 110,908 個です。取り置いた区域は、学習用の区画と場所が重なりません（プログラムで確かめています）。

**崩し方の数字について。** 「階段 10%、ハーフ 50%、塀 70%」は、3D モデルをブロックにしたときに消えそうな割合を、私が見積もったものです。実際の 3D 化 AI の出力で確かめたものではありません（関門 5 で確かめます）。

**比べる相手（基準）。** 崩したまま何もしない場合の当たりは、① で 86.5%、② で 83.6% です。崩し方が弱いので、基準が v0（48.6%）よりずっと高くなっています。**v1 は、この高い基準を上回れるかどうかが勝負です。**

**2 つの検証の読み方。**

| ① 同じマップ | ② 別のマップ | 意味 |
|---|---|---|
| 当たる | 当たる | 方法が効いている |
| 当たる | 当たらない | 方法は効くが、作風の違うマップには通じない。データの種類を増やす必要がある |
| 当たらない | 当たらない | 暗記しているだけ。データの量か、方法そのものを見直す |

**最初の成績（2,000 歩、学習を始めて約 12 分）。** 一度に全部当てる方式、256 区画。

| | ① 同じマップの別の場所 | ② 別のマップ |
|---|---|---|
| 何もしない（基準）の当たり | 86.5% | 83.6% |
| モデルの当たり | **91.4%**（基準 +4.9） | 81.4%（基準 −2.2） |
| 細部を、形も素材も当てた割合 | 40.1% | 14.2% |
| 細部を、形（種類と向き）まで当てた割合 | 42.6% | 16.1% |
| 置いた細部のうち、合っていた割合 | 58.5% | 28.8% |
| 細部の量（本物に対して） | 69% | 49% |

- **v0 とは、はっきり違います。** v0 は 3 時間かけて細部が 1% でした。v1 は 12 分で、同じマップなら 40%、別のマップでも 14% です。
- **① では、基準を上回りました。** 学習に使っていない場所でも、「どこを階段やハーフにするか」が 4 割当たっています。暗記ではなく、決まりを学べている証拠です。
- **② では、まだ基準を下回っています。** 細部を 14% 当てる一方で、ふつうのブロックを余計に変えて損をしています。今のところ、上の表の 2 行目（方法は効くが、作風の違うマップには通じにくい）に当たります。
- **この時点では、まだ 12 分でした。** 最後までの結果は、すぐ下にあります。
- **数回に分けて埋める方式は、この時点では一度に当てる方式より悪かったです。** 同じ 64 区画で比べて、① の当たりは 93.4% 対 94.8%。細部を置きすぎました（本物の 1.5 倍）。

**途中で一時停止が入りました。** 19:49 に 1,660 歩で止まり、20:23 に再開しました。止まった所から続き、時間の上限（合計 2 時間）も引き継いで、22:14 に終わりました。

## 5. 本命の方法：崩して戻す学習

### 学習のしかた

1. 本物の建築を、32×32×32 の区画に切ります。
2. 区画を崩します。解像度を 1/2 や 1/4 に落とす、色を平均の色にする、角を丸める、わざと乱す、などです。
3. LizArc に、崩した区画と「使ってよいブロックの一覧」を渡し、元のブロックを当てさせます。
4. 元の区画と 1 個ずつ比べて、外れた分だけ重みを直します。

「使ってよいブロックの一覧」も、元の区画から自動で作れます。様式（白・金・青緑など）は、この一覧で指定します。説明文は要りません。

### 作るとき（学習のあと）

| 段 | 入力 | すること | 手段 |
|---|---|---|---|
| ① 形づくり | 画像、または文章 | 粗い色つきの立体にする | 画像 → 3D 化 AI（TRELLIS.2 など）。文章 → Claude が形のプログラムを書く。あなたがゲーム内で粗く組む、も可 |
| ② 仕上げ | 粗い立体＋ブロックの一覧 | 区画ごとにマイクラのブロックへ直し、重なりを持たせてつなぐ | LizArc（学習したモデル） |
| ③ 書き出し | ブロックの並び | `.litematic` にする | 自作の書き出し係。大きいものは区画に分ける |

① を何に替えても、② はそのまま使えます。① が外れても、学習はやり直しになりません。

### モデル

- 方式は 2 つを試して、良いほうにします。**一度に全部当てる方式** と、**隠した所を数回に分けて埋める方式**（研究で、ブロックの立体に強いと報告されている方式）です。
- 大きさは、約 3,000 万個の重みから始めます。データを増やすのに合わせて、1 億、3 億と増やします。3 億が 16GB の GPU に収まるかは、まだ測っていません。
- ブロックは「種類」と「向きなどの状態」を分けて当てさせます。階段の向きやハーフの上下を、捨てずに済みます。

### 言語

| 仕事 | 言語 | 理由 |
|---|---|---|
| 建築データの読み込み、区画切り、崩し、回転・鏡写し、`.litematic` の書き出し | Rust | 何百万区画を扱うので、ここは速さが効く。Rust は導入済み |
| 学習の計算 | PyTorch | 計算のほとんどは GPU の中で行われ、言語の速さはほぼ関係しない。Rust だけで学習する道具もあるが、実例が少なく、つまずきやすい |
| 学習後に動かす部分 | Rust へ移せる | 確定後に検討 |

PyTorch は、今のパソコンには入っていません（Python は 3.15）。対応する Python を別に用意します。

### Claude Code の役割

- 工場を作る：Rust と学習のプログラムを書きます。
- 学習を回す：学習を始め、誤差と当たった割合を読み、次の設定を決めます。重みを増やすのも、ここです。
- ① の形を作る：文章から形のプログラムを書きます。
- **点数は付けません。** 良し悪しは、本物との答え合わせと、あなたの目で決めます。

### データ

| 出どころ | 量 | 条件・注意 |
|---|---|---|
| あなたの手元の建築（前回のお手本 7 作品など） | 小 | 置き場が分からなくなっています（質問 2） |
| Dream-Cubed の人の建築データ | 32³ の区画が約 36 万個（プロの建築家 1 人の 6 マップ）。使うのは元の区画の約 1.5GB | **非商用の研究のみ**。向きや飾りは残っているが、色と木の種類が抜けている（0 章） |
| 配布されているワールドや設計図 | 探せば多い | 作者が利用を許しているものだけ。1 件ずつ条件を確かめる |

データがいちばんの急所です。細かい飾りまで残った、質の高い建築が、どれだけ集まるかで上限が決まります。

## 6. 2 週間の試行と、確定の条件

| 日 | すること | 分かること |

| 3〜4 | 崩し方を作る。比べる相手（色合わせだけの変換＝Blender 案そのまま）を作って測る。公開ずみモデルの出来も見る | 基準線 |
| 5〜7 | 小さいモデルで学習。2 つの方式と、崩し方の強さを比べる | 関門 2 |

### 関門（すべて通れば確定）

| # | 関門 | 通った、と言える線（最初の値） |
|---|---|---|
| 1 | 道具が正しい | 自作の `.litematic` が Litematica で開き、階段などの向きも合っている |
| 2 | 学習が効く | 学習に使っていない建築で、ブロックを当てた割合が、色合わせだけの変換をはっきり上回る |
| 3 | 増やすと伸びる | データを 2 倍、4 倍にするたびに、使っていない建築での成績が上がる |
| 4 | あなたの目 | ゲーム内で見て、前回の 2 点を大きく超える（数字は質問 1） |
| 5 | 通しで動く | 画像 1 枚から `.litematic` まで、人の手を入れずに通る |

関門 3 が、「確定後に大量のデータで学習する」ことの裏づけになります。ここが伸びなければ、大量に学習しても無駄になります。

### 通らなかったとき

| 起きたこと | 切り替え先 |
|---|---|
| 関門 2 が通らない | まずデータを疑う（飾りが消えていないか）。次に、当てる範囲を「表面だけ」に狭める |
| 関門 3 が通らない | モデルの大きさを変える。だめなら案 B（一発生成）を同じデータで試す |
| ① の形が悪い | ① だけを替える（Claude の形のプログラム、または手で粗く組む）。② は残す |
| 実物の粗い立体でだけ崩れる | 3D 化 AI の出力を「崩した側」の見本に足して、学習し直す |

## 7. 危ない点と、確かめていないこと

- **全部が見込みです。** 今日は調査と設計だけで、プログラムは 1 行も動かしていません。
- **全体の構成は ① しだいです。** ② は、壁や屋根の仕上げを良くします。塔の配置や比率は直しません。白い宮殿の絵 1 枚から、裏側まで正しい形が出るかは分かりません。
- **像のような形は、後回しです。**
- **3D 化 AI が 16GB で動くかは未確認です。** 「低い解像度なら動く」という情報はありますが、公式の数字ではありません。
- **440×256×426 は、2 週間の範囲に入れていません。** 試行は 200 ブロック級までです。
- **2 点が何点になるかは、約束できません。** 関門 4 で、あなたの目で確かめます。
