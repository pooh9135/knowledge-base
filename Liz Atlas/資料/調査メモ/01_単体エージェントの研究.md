## Q1. Voyager（2023）の仕組み・数値・限界・公開状況

### Takeaway
Voyager は GPT-4 に Mineflayer 上で動く JavaScript を書かせ、成功したコードを「説明文の埋め込み→コード」の形でベクトルDBに貯めて再利用するエージェントで、160 回の prompting iteration で 63 種類のアイテムを集めた。ただしリポジトリの最終コミットは 2023-07-27 で、Minecraft 1.19（Fabric）でしか試されていない。止まってしまうことや、GPT-4 の幻覚、費用の高さを著者自身が限界として挙げている。

### Cited Findings
**全体の仕組み**
- GPT-4 をブラックボックス API として呼ぶだけで、モデルの重みは学習しない。人が介入しなくても探索を続ける「生涯学習」エージェントとして設計されている — [Voyager論文](https://arxiv.org/html/2305.16291)
- 構成は3つ: (1) 自動カリキュラム、(2) スキルライブラリ、(3) 反復プロンプト（環境フィードバック、実行エラー、自己検証）— [Voyager論文](https://arxiv.org/html/2305.16291)

**自動カリキュラム**
- 次のタスクは GPT-4 が提案する。目標は「できるだけ多様なものを発見すること」。
- プロンプトに入れる情報: エージェントの状態（インベントリ、装備、近くのブロックとエンティティ、バイオーム、時刻、体力、空腹度、位置）、完了したタスクと失敗したタスク、追加の文脈。
- 追加の文脈は、安い GPT-3.5 に「自分で質問して自分で答える」形で作らせる。
- カリキュラムの temperature は 0.1。
- 出典: [Voyager論文](https://arxiv.org/html/2305.16291)

**スキルライブラリ**
- スキルは「時間をかけて行う行動を実行できるコード」として保存する。
- キーは、GPT-3.5 が書いたスキル説明文の埋め込みベクトル。値はプログラム本体。
- 検索するときは「提案されたタスク＋環境フィードバック」を埋め込み、似ているスキルを上位5件取り出す。
- 単純なスキルを組み合わせて複雑なスキルを作るので、破滅的忘却が減ると論文は主張している。
- 出典: [Voyager論文](https://arxiv.org/html/2305.16291)

**反復プロンプトと自己検証**
- 3種類のフィードバックを使う: (a) `bot.chat()` で出す途中経過（例: 材料が足りない）、(b) インタプリタの実行エラーや構文エラー、(c) 別の GPT-4（critic）による成否判定と修正案。
- 1タスクにつきコード生成は最大4ラウンド。成功したらスキルライブラリに追加し、失敗したら失敗タスクとして記録してカリキュラムを先へ進める。
- 出典: [Voyager論文](https://arxiv.org/html/2305.16291)

**使ったモデル**
- コード生成、critic、カリキュラム: GPT-4（gpt-4-0314）
- 補助処理: GPT-3.5（gpt-3.5-turbo-0301）
- 埋め込み: text-embedding-ada-002
- temperature はカリキュラムが 0.1、それ以外は 0
- MineDojo の上に作られ、体の操作には Mineflayer の JavaScript API を使う
- 出典: [Voyager論文](https://arxiv.org/html/2305.16291)

**LLM に見せる制御プリミティブ**
- リポジトリの `voyager/control_primitives` フォルダには次の JS ファイルがある: `craftHelper.js`, `craftItem.js`, `exploreUntil.js`, `givePlacedItemBack.js`, `killMob.js`, `mineBlock.js`, `placeItem.js`, `shoot.js`, `smeltItem.js`, `useChest.js`, `waitForMobRemoved.js` — [GitHub control_primitives](https://github.com/MineDojo/Voyager/tree/main/voyager/control_primitives)
  - 注意: このページには「View all files」の表示があり、一覧が完全かは確認できていない。
- Odyssey 論文によると、Voyager の primitive skill は 18 個で、すべて操作系（空間系はない）— [Odyssey論文](https://arxiv.org/html/2407.15325)
- 論文の本文で読めた範囲には、API 名の一覧は見つからなかった — [Voyager論文](https://arxiv.org/html/2305.16291)

**報告された結果**（論文の数値、3回試行の平均）
- 探索: 160 prompting iteration で 63 種類のユニークアイテム。最良のベースラインの 3.3 倍。移動距離は 2.3 倍。
- 技術ツリー（到達までの iteration 数）:
  - 木の道具: 6±2（約15.3倍速い）
  - 石の道具: 11±2（約8.5倍）
  - 鉄の道具: 21±7（約6.4倍）
  - ダイヤの道具: 102。3回中1回しか到達していない。ベースラインは1回も到達しない。
- 新しいワールドでのゼロショット（どれも3/3成功）: ダイヤのツルハシ 19±3、金の剣 18±7、溶岩バケツ 21±5、コンパス 18±2 iteration。ベースラインは 50 iteration の上限内では失敗した（スキルライブラリを付けた AutoGPT だけは一部成功）。
- アブレーション:
  - カリキュラムをランダムにすると、発見アイテムが 93% 減る
  - 自己検証を外すと 73% 減る
  - コード生成を GPT-3.5 にすると、GPT-4 版の方が 5.7 倍多くアイテムを見つける
  - スキルライブラリがないと、後半で進歩が頭打ちになる
- 出典: [Voyager論文](https://arxiv.org/html/2305.16291)

**人間が手伝う使い方**
- 人間が critic になって視覚的なフィードバックを返したり、カリキュラム役になって建築を段階に分けたりできる。この方法で作ったネザーポータルと家の例が載っている。
- Voyager 自体には視覚がない（当時の GPT-4 API はテキストのみ）。
- 出典: [Voyager論文](https://arxiv.org/html/2305.16291)

**著者が挙げた限界**
- 費用: GPT-4 は GPT-3.5 の約15倍高い。
- 不正確さ: 途中で止まってしまうことがある。自己検証が成功を見逃すことがある（例: クモを倒した証拠として糸を認識しない）。
- 幻覚: カリキュラムが存在しないアイテム（銅の剣）を提案する。コード生成が丸石を燃料に使ったり、存在しない関数を呼んだりする。
- 出典: [Voyager論文](https://arxiv.org/html/2305.16291)

**費用と呼び出し回数**
- 読めた範囲では、1回の実行にかかる総費用や総時間は書かれていなかった。
- 後の Odyssey 論文は「GPT-4 で Voyager を動かすと1実験あたり数千ドルかかる」と見積もっている（他者による見積もり）— [Odyssey論文](https://arxiv.org/html/2407.15325)

**公開状況**（リポジトリ、2026-11-14 確認）
- ライセンスは MIT。研究用で、NVIDIA の公式製品ではない。
- 試験済みの環境は `fabric-loader-0.14.18-1.19`、つまり Minecraft 1.19 と Fabric。
- 必要なもの: Python 3.9 以上、Node.js 16.13.0 以上、Fabric mod、OpenAI API キー。
- Mineflayer 部分は `voyager/env/mineflayer` にある。
- ログインは Azure ログイン推奨。README の手順では、LAN 公開したワールドでチートを有効にする（Creative / Peaceful の設定例が書かれている）。
- 学習結果は `ckpt_dir` と `resume` で再開でき、`skill_library_dir` で既存のスキルを読み込める。
- スター数 7.3k、コミット数 35。
- 出典: [GitHub README](https://github.com/MineDojo/Voyager)
- 最終コミット: 2023-07-27（PR #116 のマージ）。直前の 2023-07-23 には「prismarine-block の非互換リリースに対する版固定」、2023-07-20 には「chromadb の新版で壊れたので requirements を修正」というコミットがある — [GitHub commits](https://github.com/MineDojo/Voyager/commits/main)

### Inferences
（ここは私の解釈）
- 最終コミットが 2023 年で Minecraft 1.19 用なので、Minecraft 26.1.2 と Mineflayer 4.39 の環境にそのまま載せられる可能性は低い。依存パッケージの版ずれで壊れた記録もある。コードは「設計を読む教材」と考え、移植前提にはしないほうが安全。
- `mineBlock` / `craftItem` / `placeItem` / `smeltItem` / `useChest` / `exploreUntil` くらいの粒度の決定論的な関数を人間が書いておき、LLM にはそれを組み合わせる役だけを任せる。この分担は「LLM は例外時の監督だけ」という設計に合う。
- 自己検証を外すと発見数が 73% 減るという結果は、「スキルが成功したかを自動で判定すること」の重要さを示していると読める。ただし Voyager は判定にも GPT-4 を使っている。インベントリの差分のように機械的に判定できる部分はコードで判定する方が安く、確実だと考えられる。
- 「最大4ラウンドで諦めて次へ進む」という打ち切りルールは、無人運転で同じ失敗を無限に繰り返さないための参考になる。

### Gaps
- 1回の実行の実時間、LLM 呼び出しの総数、ドル換算の費用は、読めた範囲の論文には見つからなかった（付録の後半約5万文字は未読）。
- control_primitives の一覧が完全かどうか、各関数の引数は、ソース未読のため未確認。
- 論文の実験がサバイバルかクリエイティブかは、読めた範囲では確認できなかった（README の設定例はクリエイティブ/ピースフル）。

## Q2. GITM・DEPS・JARVIS-1・Odyssey と 2025〜2026年の後続研究

### Takeaway
どの研究も「LLM が目標を部分目標に分解する → 決まった行動の集合（手書きスクリプト、学習した制御器、または Mineflayer のスキル）で実行する → 失敗を文章で説明して計画し直す → 成功例を記憶する」という同じ骨格を持っている。中でも GITM（成功した行動の列を記憶し、要約して再利用する）と Odyssey（Mineflayer 上の 40 個の primitive と 183 個の compositional skill、MIT ライセンス）は、このプロジェクトの設計に一番近い。

### Cited Findings
**GITM（Ghost in the Minecraft, 2023）**

仕組み — 出典: [GITM論文](https://arxiv.org/html/2305.17144)
- 環境は MineDojo の地上（オーバーワールド）。目標は地上の 262 アイテムをすべて手に入れること。
- LLM Decomposer: wiki とレシピの知識を使って、目標を「部分目標の木」に分解する。各目標は (object, count, material, tool, info) の組で表す。木を後順で辿って実行順を決める。
- LLM Planner: 構造化された行動の列を計画する。
- LLM Interface: 構造化行動を、キーボードとマウスの操作に変える手書きスクリプト。
- 構造化行動は9種類: equip, explore, approach, mine/attack, dig_down, go_up, build, craft/smelt, apply。MineDojo の 3,141 タスクを LLM に分解させ、よく出る行動をまとめて決めた。
- テキスト記憶: 部分目標ごとに、成功した行動の列を辞書に保存する。同じ部分目標で5本たまったら（N=5）、LLM が1本の参照計画に要約して先頭に置く。
- 失敗の扱い: 行動のたびに、インベントリ、バイオーム、高さ（y）、地上か地下か、成功したか、失敗ならその理由を返し、失敗した段階から計画し直す。
- 上限: 部分目標ごとに LLM 呼び出し 30 回まで。1エピソード 10 分（12,000 ステップ）。

結果 — 出典: [GITM論文](https://arxiv.org/html/2305.17144)
- ObtainDiamond の成功率: GITM 67.5%、VPT 20.0%、DEPS 0.6%、DreamerV3 0.01%。
- 262 アイテムすべてで成功率が 0 より大きかった。
- 計算資源: GPU なし、32 コアの CPU ノード1台で約2日。比較として VPT は 6,480 GPU 日、DreamerV3 は 17 GPU 日。
- アブレーション: 目標分解を入れると石の斧の成功率が 5% → 67.5%。記憶を入れると鉄のツルハシが 95.0%。

限界（本文中の記述） — 出典: [GITM論文](https://arxiv.org/html/2305.17144)
- 構造化行動は手書きで、学習による代替は試していない。
- 観測は LiDAR の光線とボクセルで、RGB 画像ではない。光線がまばらなので物体を見落とすことがある。
- バイオームに強く依存するアイテムがある。
- 計画には gpt-3.5-turbo を使っている。

公開状況
- GitHub（OpenGVLab/GITM）にあるのは `figs`、`GITM.pdf`、`README.md` だけで、ソースコードはない。ライセンス表示もない。コミット14件 — [GitHub](https://github.com/OpenGVLab/GITM)

**DEPS（Describe, Explain, Plan and Select, NeurIPS 2023）**

仕組み — 出典: [DEPS論文HTML](https://arxiv.org/html/2302.01560)
- Descriptor: 部分目標が失敗したときだけ動き、状態と結果を文章にする。
- Explainer: LLM が失敗の理由を説明する。
- Planner: 同じ LLM が説明を踏まえて計画し直す。
- Selector: 並べて実行できる候補の部分目標を「残りのステップ数の見積もり」で並べ替える、学習済みのモジュール（Impala CNN）。
- 制御器は行動模倣（behavior cloning）で学習した目標条件付きポリシー。262 個の目標と、42 個に離散化した行動を持つ。MineRL では Steve-1、MineDojo では MC-Controller を使う。

タスクと結果 — 出典: [DEPS論文HTML](https://arxiv.org/html/2302.01560)
- MCU の 71 タスク（8グループ）、各30回。付録の表には ID が 76 個あり、本文の「71」と合わない。
- 環境: MineDojo（1.11.2）、MineRL（1.16.5）、MC-TextWorld（1.19.2）。
- 平均成功率: DEPS 48.56%、最良のベースライン（CaP）25.77%。
- ObtainDiamond は 0.59%。
- 計画し直す回数を増やすほど成功率が上がる。Codex ではおよそ7〜8ラウンドが上限だった。

限界 — 出典: [DEPS論文HTML](https://arxiv.org/html/2302.01560)
- 非公開の LLM に依存している。
- 一歩ずつ計画するやり方がボトルネックになる。
- 行き止まり（dead end）のような問題は、今回の環境では出てこなかった可能性がある。

公開: コードは https://github.com/CraftJarvis/MC-Planner（未読）— [DEPS abs](https://arxiv.org/abs/2302.01560)

**JARVIS-1（2023）**

仕組み — 出典: [JARVIS-1論文](https://arxiv.org/html/2311.05997)
- 計画役: MineCLIP と GPT 系 LLM を組み合わせたマルチモーダル LLM。
- 実行役: 採掘は STEVE-1。クラフトと精錬は環境の機能でそのまま実行する。
- 記憶: 成功した軌跡だけを {task, state, plan} の形で保存する。CLIP のテキスト類似度で候補を絞り、画像の類似度で並べて、プロンプトに入れる。
- self-check: 実行する前に、各段階のインベントリを予測して前提条件を確認する。
- self-explain: 失敗した後に、どの段階が悪かったかを説明する。
- 実行できる計画にたどり着くまでの計画し直しは、通常2〜3回（DEPS は6回以上）。

結果 — 出典: [JARVIS-1論文](https://arxiv.org/html/2311.05997)
- 200 以上のタスク（11グループ）、各30回以上。
- 成功率: Wood 88.84%、Iron 34.63%、Gold 6.85%、Diamond 8.99%。
- ObtainDiamondPickaxe: 20 分で約6.2%、60 分（72,000 ステップ）で約12.5%。
- 人間の熟練者は 10 分でダイヤのツルハシ約12%。
- 自己改善: 並列に動く複数の環境で記憶を共有する。4エポックで 425 本の成功軌跡がたまり、記憶が増えるほど成功率が上がった（勾配による学習はしない）。
- GPT が作るカリキュラムは、人間が書いたものやランダムなものより良かった。

環境と限界 — 出典: [JARVIS-1論文](https://arxiv.org/html/2311.05997)
- Minecraft 1.16.5、サバイバル。ただしピースフル、常に昼、keepInventory 有効。
- 限界: ダイヤ系のタスクでは、計画は正しくても制御器（STEVE-1）が短い指示を実行できないことが詰まりの原因になる。信頼性は1桁台〜約12.5%にとどまる。
- 読めた範囲ではコード公開の記述はなかった。

**Odyssey（2024年に arXiv、IJCAI 2025 採択）**

スキルライブラリ — 出典: [Odyssey論文](https://arxiv.org/html/2407.15325)
- Mineflayer の JavaScript API の上に primitive skill を 40 個（操作系32、空間系8）作り、その上に compositional skill を 183 個作った。
- compositional skill は mineX / craftX / smeltX / plantX / breedX / killX の形。前提が足りなければ、それを作るスキルを先に再帰的に実行する。
- スキル説明文を Sentence Transformer で埋め込み、上位5件を取り出す。
- 構成は planner / actor / critic。critic はインベントリの変化で部分目標の達成を確認し、失敗を振り返る。

結果 — 出典: [Odyssey論文](https://arxiv.org/html/2407.15325)
- スキルライブラリ単体の性能（各120回）: 作業台は2分以内に 95.8%。ダイヤ入手は平均 6.48 分で、5分以内の成功率 21.7%、10分以内なら 92.5%。
- MineMA: LLaMA-3-8B / 70B を約39万件（390,317件）の wiki 由来 Q&A で LoRA 微調整したもの。8B 版は A6000 1枚で学習できる。
- 自律探索では、MineMA-8B が Voyager（GPT-4o-mini / GPT-3.5 版）、DEPS、ReAct、AutoGPT を上回った。
- スキルライブラリを外すと、8B モデルだけでは実行できるコードをほとんど書けない。

限界 — 出典: [Odyssey論文](https://arxiv.org/html/2407.15325)
- オープンソース LLM の幻覚。
- テキストのみで、視覚は扱っていない。

公開状況 — 出典: [GitHub](https://github.com/zju-vipa/Odyssey)
- コードは MIT ライセンス。Q&A データセットは CC BY-NC-SA 3.0（非商用）。
- 必要なもの: Node.js 16.13.0 以上、Python 3.9 以上。
- コミット141件、スター411。フォルダに `Multi-Agent` がある。
- 最新ニュースは 2025-04-29（IJCAI 採択）。
- 対応する Minecraft の版は README に書かれておらず、確認できなかった。

**2025〜2026年の後続研究**
- MineNPC-Task（v2 は 2026-01-09）— 出典: [MineNPC-Task](https://arxiv.org/html/2601.05215)
  - Mineflayer の公開されている操作だけを使い、管理者コマンドや、読み込まれたチャンクの外の走査を禁止する「bounded-knowledge」方針で評価する。
  - 熟練プレイヤー8人が作った 44 タスク（216 部分タスク）。
  - GPT-4o で 216 件中 71 件が失敗（約33%）。
  - 失敗の内訳: コードや実行の失敗 24、インベントリや道具の誤用 10、文脈の誤解 7、参照の誤り 6、移動 5（合計52で、残り19件は分類なし）。
  - 生成した JS は軽いレビューを通し、再試行は最大2〜3回（図では K≤3）。
  - 記憶は型付きで、ランドマーク、作ったもの、好み、約束を保存し、情報の出どころ（見た／言われた／推測した）を付ける。
  - 限界: GPT-4o だけの結果。部分的な進捗を評価できない。経路探索やチャンク読み込みによるばらつきがある。
- VistaWise（arXiv 2508.18722, EMNLP 2025）: Mineflayer ではなく画面認識で動く。「API の高レベル行動は自律性を制限する」と主張しているらしい — [検索結果の要約のみ](https://arxiv.org/pdf/2508.18722v3)（本文未読）
- MineAnyBuild（arXiv 2505.20148）: 建築の空間計画のベンチマークで 4,000 タスク。APT（arXiv 2411.17255）: テキストから設計図を作って建築する — [検索結果](https://huggingface.co/papers/2411.17255)（どちらも本文未読）
- arXiv 2605.28390（階層的なスキルのメタ進化）: MineDojo の基本行動で評価しており、Mineflayer 系とは直接比べられないと述べているらしい — [検索結果](https://arxiv.org/pdf/2605.28390)（本文未読）

### Inferences
（ここは私の解釈）
- Odyssey の「前提が足りなければ前提を作るスキルを再帰的に呼ぶ」仕組みと、GITM の (object, count, material, tool) による目標の木は、LLM なしでも決定論的なコードで書ける（レシピ表から前提を解く）。LLM は分解の主役から外せる。
- JARVIS-1 の「実行前に前提条件をシミュレーションする self-check」は、決定論的なコードでの事前チェック（インベントリ、道具、空きスロット）に置き換えられる。
- MineNPC-Task の失敗内訳では「コードや実行の失敗」が最も多かった。LLM に毎回新しいコードを書かせる方式は事故の元になりやすい、と読める。

### Gaps
- Odyssey の対応 Minecraft 版と Mineflayer 版は確認できなかった（README に記載なし。package.json は未読）。
- JARVIS-1 のコード公開状況とライセンスは未確認。
- 2025〜2026 年の Mineflayer 系の後続研究は、MineNPC-Task 以外には見つけられなかった（検索は2回だけなので、見落としの可能性がある）。

## Q3. VPT・DreamerV3・MineDojo/MineCLIP・STEVE-1（学習型、浅い調査）

### Takeaway
ニューラルネット型は、大量のデータと計算資源（VPT は約7万時間の動画と約6,480 GPU 日）を使っても、ダイヤのツルハシの成功率は数%にとどまる。NN の学習をしない今回のプロジェクトにとっては、主に背景知識として役立つ。

### Cited Findings
**VPT（2022-06）**（ar5iv の一部を読んだ）— 出典: [VPT ar5iv](https://ar5iv.labs.arxiv.org/html/2206.11795)
- データ: ラベルなしのネット動画 約7万時間（約27万時間の中から選別）。ラベル付きの委託データ 1,962 時間（収録総量は約4,500時間。約2,000ドル分で十分だったと見積もっている）。
- モデル: 基盤モデルは約5億パラメータ。
- 計算資源: V100 を 720 枚で約9日（約6,480 GPU 日）。
- 結果: 強化学習で微調整した後、鉄のツルハシは80%以上、ダイヤ入手は約20%、ダイヤのツルハシは約2.5%。人間の熟練者がダイヤの道具を作るには、20分以上（24,000 行動）かかるとしている — [VPT abs](https://arxiv.org/abs/2206.11795)
- 限界:
  - 過去の観測だけを入力にするので、特定のタスクを指示できない。
  - ゼロショットでのクラフト作業台の作成は 0.19 個/時（人間は 5.44 個/時）。
  - KL 損失なしで強化学習すると、破滅的忘却が起きる。

**DreamerV3**（**アブストラクトのみ**）— 出典: [DreamerV3 abs](https://arxiv.org/abs/2301.04104)
- 人間のデータもカリキュラムも使わずにダイヤを集めた最初のアルゴリズム、と主張している。
- 1つの設定で 150 以上のタスクで専用手法を上回った。
- 計算量はアブストラクトに書かれていない。GITM 論文は 17 GPU 日と引用している — [GITM論文](https://arxiv.org/html/2305.17144)

**MineDojo / MineCLIP（2022）**（HTML の一部を読んだ）— 出典: [MineDojo論文](https://arxiv.org/html/2206.08853v2)
- タスク: programmatic 1,581 件、creative 1,560 件。
- 知識ベース: YouTube 73万本以上（約33年分）、wiki 6,735 ページ、Reddit 34万投稿以上。
- MineCLIP は、16秒の動画と字幕の組 64万件で学習した、報酬を出すモデル。
- 新しいタスクでのゼロショット成功率は低い（豚狩り 1.3%）が、強化学習で微調整すると 46.0% になる。
- 対応する Minecraft の版は、読めた範囲には書かれていなかった。DEPS 論文によると MineDojo は 1.11.2 — [DEPS論文](https://arxiv.org/html/2302.01560)

**STEVE-1（2023）**（**アブストラクトのみ**）— 出典: [STEVE-1 abs](https://arxiv.org/abs/2306.00937)
- VPT を MineCLIP の潜在空間で指示に従うように調整したもの。
- 計算費用は約60ドル。
- 序盤の13タスク中12タスクを達成した。
- 重み、学習スクリプト、評価ツールを公開している。

### Inferences
（ここは私の解釈）
- 今回のプロジェクトの「NN の学習はしない」方針は妥当に見える。GITM が「GPU なし、CPU だけで学習 VPT を大きく上回った」と報告していることも、構造化行動とスクリプトで作るほうが有利だという傍証になる。

### Gaps
- DreamerV3 と STEVE-1 の計算量やデータ量の詳細は、本文を読んでいないので未確認。
- MineDojo の限界節は未読。

## Q4. 失敗からの回復・長時間の信頼性・無人運転の証拠

### Takeaway
どの論文も評価は短いエピソード単位（10〜60分、あるいは prompting iteration の回数）で、**数時間を超える無人運転や、大規模な採掘・建築を報告したものは見つからなかった**。失敗からの回復は「失敗を文章にする → LLM が計画し直す → 回数の上限で打ち切る」という形が共通している。

### Cited Findings
- 各論文の評価の長さ:
  - GITM: 1エピソード10分、部分目標ごとに LLM 呼び出し30回まで — [GITM](https://arxiv.org/html/2305.17144)
  - JARVIS-1: 最長60分（72,000 ステップ）。ピースフル、常に昼、keepInventory という易しい設定 — [JARVIS-1](https://arxiv.org/html/2311.05997)
  - DEPS: 最長 12,000 ステップ — [DEPS](https://arxiv.org/html/2302.01560)
  - Voyager: 160 iteration。試行回数は3回 — [Voyager](https://arxiv.org/html/2305.16291)
  - VPT: 強化学習のエピソードは10分 — [VPT](https://ar5iv.labs.arxiv.org/html/2206.11795)
- 打ち切りルール:
  - Voyager は1タスク4ラウンドで諦めて失敗として記録し、次のタスクへ進む — [Voyager](https://arxiv.org/html/2305.16291)
  - MineNPC-Task は再試行を最大2〜3回にしている — [MineNPC-Task](https://arxiv.org/html/2601.05215)
- 著者が書いている長時間運転への障害:
  - Voyager は止まってしまうことがある — [Voyager](https://arxiv.org/html/2305.16291)
  - MineNPC-Task は、経路探索とチャンク読み込みによるばらつきを挙げている — [MineNPC-Task](https://arxiv.org/html/2601.05215)
- 建築:
  - Voyager の建築例は、人間がカリキュラム役や critic 役として助けたもの — [Voyager](https://arxiv.org/html/2305.16291)
  - MineAnyBuild や APT は「設計図を作る」評価が中心とみられるが、本文は未読 — [検索結果](https://huggingface.co/papers/2411.17255)

### Inferences
（ここは私の解釈）
- 「16チャンクを無人で掘り切る」「litematic の大型建築を完成させる」といった時間規模での信頼性は、学術研究では実証されていないと考えたほうがよい。長時間の安定性（切断からの再接続、死亡、空腹、インベントリ満杯、チャンクの読み込み待ち）は、このプロジェクトが自分で作り込み、自分で計測する必要がある領域。

### Gaps
- 数時間以上の連続運転に関する報告は、確認した範囲にはなかった。読んでいない付録や、2025年以降の論文に存在する可能性は残る。

## Q5. 「LLM は例外時の監督だけ」設計に移せるアイデア

### Takeaway
移しやすいのは次の4つ: (1) 説明文の埋め込みで検索できる「コードとしてのスキル」、(2) インベントリの差分などによる機械的な成否判定、(3) 失敗した状況・理由・修正をまとめた構造化ログと、成功列の要約記憶、(4) 技術ツリーに沿った易→難のカリキュラム。

### Cited Findings
- スキルの形式:
  - Voyager: キーは「説明文の埋め込み」、値は「コード」。上位5件を検索し、成功したときだけ登録する — [Voyager](https://arxiv.org/html/2305.16291)
  - Odyssey: 説明文を Sentence Transformer で埋め込み、上位5件を検索する。スキル名は mineX / craftX のように規則的 — [Odyssey](https://arxiv.org/html/2407.15325)
- 成否判定:
  - Voyager は GPT-4 の critic を使い、外すと発見数が73%減る — [Voyager](https://arxiv.org/html/2305.16291)
  - Odyssey の critic はインベントリの変化で達成を確認する — [Odyssey](https://arxiv.org/html/2407.15325)
  - MineNPC-Task は、タスクごとに機械的に確認できる validator を付ける — [MineNPC-Task](https://arxiv.org/html/2601.05215)
- 失敗の記録と、成功例の記憶:
  - GITM: 失敗理由のフィードバックを返す。成功列を5本ためたら要約して参照計画にする — [GITM](https://arxiv.org/html/2305.17144)
  - DEPS: 失敗したときだけ状況を文章にして（descriptor）、説明させる（explainer）— [DEPS](https://arxiv.org/html/2302.01560)
  - JARVIS-1: 成功した計画だけを {task, state, plan} で保存し、事前に前提条件をチェックする — [JARVIS-1](https://arxiv.org/html/2311.05997)
  - MineNPC-Task: 記憶に情報の出どころを付け、失敗の種類を分類する — [MineNPC-Task](https://arxiv.org/html/2601.05215)
- カリキュラム:
  - Voyager: カリキュラムをランダムにすると93%減る — [Voyager](https://arxiv.org/html/2305.16291)
  - JARVIS-1: 技術ツリーに沿ったカリキュラムが、人間が書いたものやランダムなものより良い — [JARVIS-1](https://arxiv.org/html/2311.05997)

### Inferences
（ここは私の解釈）
- 普段の動作はすべて人間が書いた（または承認した）決定論的なスキルが担う。LLM を呼ぶのは「スキルが上限回数まで失敗した」「validator が不合格を返した」ときだけにする。こうすると、Voyager と比べて LLM の呼び出し回数と費用を大きく減らせると考えられる。
- 成否判定は、まず機械的な validator（インベントリの差分、ブロックの状態、座標）で行い、LLM の critic は判定できないケースだけに回す。
- 失敗ログには「状態のスナップショット（インベントリ、y座標、バイオーム、周囲）＋失敗の種類＋理由＋試した対処」を記録する。GITM のフィードバックの項目と、MineNPC-Task の失敗分類を参考にできる。
- LLM が提案した修正版スキルは、すぐ本番に入れない。validator で合格した後に登録する（Voyager の「成功したときだけ登録」を、より厳しくしたもの）。
- カリキュラムは「1チャンクの採掘 → 複数チャンク → 小さな建築 → litematic 全体」の順で、技術ツリー型の段階評価にする。
- 注意: Voyager の 63 アイテムや GITM の 67.5% といった数値は、評価環境（MineDojo、ピースフルなど）が違うので、このプロジェクトの目標にそのまま当てはめることはできない。

### Gaps
- LLM を監督役に限った設計を直接評価した学術研究は、見つけられなかった。
